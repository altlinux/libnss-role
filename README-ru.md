# libnss-role

Библиотека для NSS и набор инструментов для администрирования ролей и привилегий.
Этот README также доступен на [английском (English)](README.md)

## Описание

Модуль ролей - это модуль для службы переключения имён [NSS](https://en.wikipedia.org/wiki/Name_Service_Switch).
Модуль реализует возможность добавления групп в группы. Для администрирования модуля ролей реализованы специальные вспомогательные утилиты, которые рассматривают все группы поделёнными на две категории: роли и привилегии.

`libnss-role` позволяет достичь следующего:

* пусть пользователь `vasya` состоит в группе `users`;
* мы хотим, чтобы все пользователи, состоящие в группе `users`, автоматически считались членами группы `cdrom`, но не хотим каждого члена группы `users` вручную добавлять в `cdrom`;
* `libnss-role` делает так, чтобы, когда у `glibc` запрашивают, в каких группах состоит пользователь, "изменять" ответ в соответствии с описанным выше правилом.

В дистрибутивах GNU/Linux почти все программы и библиотеки слинкованы с системной библиотекой `libc.so.6` (glibc), а значит, что, если они используют стандартные методы получения информации о пользователе, `libnss-role` отработает. Если исполняемый файл статично слинкован с любой libc или иными методами использует не системную libc, `libnss-role` не отработает для запросов от этой программы.

### Привилегия
Обычная POSIX-группа, которая может быть назначена пользователю.
После этого пользователь может совершать действия, соответствующие данной привилегии.
К привилегиям относятся такие группы, как `cdwriter`, `audio`, `serial`, `virtualbox` и др.

### Роль
Роль так же является POSIX группой, но её предназначение указывать, на характерную деятельность, которую выполняет пользователь, работая за компьютером.
Такими группами могут быть группы `admin`, `user`, `power_user`, `developer` и др.

Для того, чтобы пользователь мог выполнять определённую роль ему могут понадобиться определённые права (привилегии), поэтому полезно уметь назначать привилегии как непосредственно пользователю (как это делается в POSIX), так и косвенно добавлять ему наборы привилегий через назначение роли. Например пользователь, которому назначена роль admin мог бы получать кроме группы admin, ещё и группы-привилегии wheel, ssh, root и пр.

Модуль ролей позволяет реализовать подобное назначение прав пользователям системы. Группы-роли назначаются непосредственно пользователю, а группы-привилегии назначаются как пользователю непосредственно, так и группам-ролям. Деление групп на два сорта условно, и администратор может управлять им самостоятельно.

## Сборка

### Зависимости

* **CMake 3.10+** и компилятор C для сборки
* файлы для разработки **PAM** (`libpam0-devel` в ALT, `pam-devel` или `libpam0g-dev` в других дистрибутивах)
* **cmocka** и **nss_wrapper** для модульных тестов (`-DENABLE_TESTS=OFF` для сборки без тестов)

Сборка выполняется так:

```
mkdir build
cd build
cmake ..
make
ctest
```

Модульные тесты также запускаются при `make`. Чтобы дополнительно запускать их под valgrind, укажите
`-DENABLE_TESTS_VALGRIND=ON`.

Каталоги установки можно изменить параметрами `-DNSS_LIBDIR=`, `-DROLE_LIBDIR=` и `-DMANDIR=` (для страниц man8).

Затем нужно включить модуль. Откройте `/etc/nsswitch.conf` и добавьте `role` в конец строки, начинающейся с `group:`.
Должно получиться примерно так:
```
group: files ldap role
```

## Администрирование модуля

### Файлы конфигурации
Для хранения информации о ролях модуль использует файл `/etc/role`, файлы в каталоге `/etc/role.d` и системную базу групп (`/etc/group`, LDAP, winbind...).
Формат описан в `role(5)`.

`/etc/role` хранит дополнительную информацию о вхождении групп в группы.
Каждая строка в файле `/etc/role` имеет следующий формат:
```
<роль>:<группа>[,<группа>]*
```
где `<роль>` и `<группа>` — имена групп или числовые идентификаторы групп.

Группа до `:` — это роль, её участники будут включены в другие группы.
Группы после `:` — это группы, которые получают участники роли.
Вложенные группы раскрываются рекурсивно.

* Имена групп могут содержать пробелы (например, `domain users`) и могут быть заключены в двойные кавычки.
* `#` начинает комментарий.
* Несколько строк для одной роли объединяются.
* Несуществующие группы пропускаются.

Рассмотрим пример. Пусть есть пользователь `pupkin` и в `/etc/group` есть записи:
```
group1:x:1:pupkin
group2:x:2:pupkin
group3:x:3:
group4:x:4:
group5:x:5:
group6:x:6:
```

А файл `/etc/role` содержит:
```
group2:group3,group4
group4:group5,group6
```

При такой конфигурации `pupkin` получит все группы:
* `group1` и `group2` назначены ему непосредственно;
* `group3` и `group4` назначены группе `group2`;
* `group5` и `group6` назначены группе `group4`.

Та же конфигурация с числовыми идентификаторами — `2:3,4` и `4:5,6`.

Дополнительную конфигурацию, например устанавливаемую пакетами, можно размещать в файлах `/etc/role.d/*.role`.
Они читаются после `/etc/role` и объединяются с ним.
Файл `/etc/role.d/РОЛЬ.role`, описывающий роль `РОЛЬ`, — это файл *системной роли*.

### Административные утилиты
Есть три утилиты: `roleadd`, `roledel` и `rolelst`.
По умолчанию `roleadd` и `roledel` изменяют `/etc/role`. С `-f ФАЙЛ.role` они изменяют `/etc/role.d/ФАЙЛ.role`,
с `-S` — файл системной роли `/etc/role.d/РОЛЬ.role`.

#### roleadd
```
roleadd [-s] [-m] [-f ФАЙЛ.role | -S] РОЛЬ [ГРУППА*]
```

Добавляет роль (если её нет) и назначает ей привилегии и роли.

`РОЛЬ` — имя роли, должно совпадать с именем существующей группы.

`ГРУППА` — имя роли или привилегии.

С ключом `-s` группы роли заменяются указанными; по умолчанию они добавляются.
С `-m` несуществующие группы пропускаются вместо ошибки.

#### roledel
```
roledel [-m] [-f ФАЙЛ.role | -S] РОЛЬ [ГРУППА*]
```
или
```
roledel -r [-f ФАЙЛ.role | -S] РОЛЬ
```

Удаляет привилегии из ролей или сами роли (вторая форма).

#### rolelst
```
rolelst [-n] [-V] [-f ФАЙЛ.role | -S [РОЛЬ]] [РОЛЬ*]
```

Показывает роли из `/etc/role` и `/etc/role.d` с именами групп (`-n` показывает числовые идентификаторы).
Если указаны `РОЛЬ`, показываются только эти роли.
`-f ФАЙЛ.role` показывает роли из одного файла, `-S` — системные роли, `-V` — отдельно `/etc/role` и объединённую конфигурацию.
